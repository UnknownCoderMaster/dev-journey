# Generated as Identity Column — Junior B

## 1. What (Nima?)

**`GENERATED ... AS IDENTITY`** — SQL STANDARTIGA (SQL:2003)
MOS, PostgreSQL 10+ DA QO'SHILGAN, **AVTOMATIK O'SUVCHI ID
USTUN YARATISH SINTAKSISI** — ESKI `SERIAL` TIPINING, ZAMONAVIY,
STANDARTLASHTIRILGAN O'RNI BOSUVCHISI. IKKI VARIANTGA EGA:
**`GENERATED ALWAYS AS IDENTITY`** (QAT'IY — QO'LDA QIYMAT
KIRITISHGA YO'L QO'YMAYDI) VA **`GENERATED BY DEFAULT AS
IDENTITY`** (ERKINROQ — QO'LDA QIYMAT KIRITISHGA RUXSAT
BERADI).

## 2. Real hayot analogiyasi

**Identity Column — NAVBAT RAQAMINI BERUVCHI AVTOMAT
MASHINA.** Bank yoki KLINIKADA — HAR MIJOZ KELGANDA, AVTOMAT
MASHINA, O'ZI, KEYINGI RAQAMNI (masalan "156") CHIQARADI —
MIJOZ O'ZI RAQAM YOZMAYDI. `GENERATED ALWAYS` — BU, "MIJOZ
UMUMAN O'Z RAQAMINI YOZOLMAYDI" DEGANI (avtomat mashina —
YAGONA MANBA). `GENERATED BY DEFAULT` — "ODATDA AVTOMAT
BERADI, LEKIN MA'MUR ISTALGAN VAQTDA QO'LDA HAM RAQAM
BERISHI MUMKIN" DEGANI (masalan, ESKI TIZIMDAN MA'LUMOT
KO'CHIRISHDA).

## 3. Why (Nega kerak?)

`SERIAL` — TEXNIK JIHATDAN, **HAQIQIY "IDENTITY" EMAS** —
U, SHUNCHAKI, ALOHIDA `SEQUENCE` OBYEKTI + `DEFAULT nextval
(...)` KOMBINATSIYASI, VA SQL STANDARTIGA MOS EMAS (boshqa
DB'larga — masalan SQL Server, Oracle — KO'CHIRISHDA
MUAMMOLI). `GENERATED AS IDENTITY` — **SQL:2003 STANDARTIGA
MOS**, VA MUHIMROQ — **QO'LDA QIYMAT KIRITISHNI NAZORAT
QILISH IMKONIYATINI** BERADI (`ALWAYS` — TO'LIQ TAQIQLAYDI),
BU — ID'LARNING NAZORATSIZ, TASODIFIY O'ZGARISHINING OLDINI
OLADI.

## 4. Internals (Ichki mexanizm)

### `SERIAL` — QANDAY ICHKI QURILGAN

```sql
CREATE TABLE t (id SERIAL PRIMARY KEY);

-- Yuqoridagi, ICHKARIDA, AVTOMATIK RAVISHDA, quyidagiga TENG:
CREATE SEQUENCE t_id_seq;
CREATE TABLE t (id INTEGER NOT NULL DEFAULT nextval('t_id_seq') PRIMARY KEY);
ALTER SEQUENCE t_id_seq OWNED BY t.id;
```

```
SERIAL — ODDIY DEFAULT MEXANIZMI ORQALI ISHLAYDI — bu, ODDIY
FOYDALANUVCHI, INSERT SO'ROVIDA, ID USTUNIGA, ISTALGAN
QIYMATNI (masalan `INSERT INTO t (id) VALUES (999999)`) ANIQ
YOZIB YUBORISHI MUMKINLIGINI ANGLATADI — SEQUENCE, BU HOLATDAN
"XABARSIZ" QOLADI (KEYINGI nextval() — HALI HAM O'ZINING
ICHKI SCHYOTCHIGIDAN DAVOM ETADI, YANGI, KO'RSATILGAN
QIYMATDAN EMAS) — bu, KELAJAKDA, DUPLIKAT KEY XATOLIKLARIGA
OLIB KELISHI MUMKIN.
```

### `GENERATED ALWAYS` — YOZISHNI QAT'IY TAQIQLAYDI

```sql
CREATE TABLE t (id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY, name TEXT);

INSERT INTO t (id, name) VALUES (999, 'test');
-- ❌ ERROR: cannot insert into column "id"
-- DETAIL: Column "id" is an identity column defined as GENERATED ALWAYS.
```

```
GENERATED ALWAYS — ODDIY INSERT'da, ID USTUNIGA ANIQ QIYMAT
YOZISHGA UMUMAN YO'L QO'YMAYDI — BU, ID'LARNING TO'LIQ, DB
TOMONIDAN NAZORAT QILINISHINI KAFOLATLAYDI. Agar HAQIQATDA
ANIQ QIYMAT KIRITISH KERAK BO'LSA (masalan DATA MIGRATSIYA
QILISHDA) — MAXSUS `OVERRIDING SYSTEM VALUE` SINTAKSISI
ISHLATILISHI SHART:

INSERT INTO t (id, name) OVERRIDING SYSTEM VALUE VALUES (999, 'test'); -- ✅ Ishlaydi
```

### Sequence Cache VA Gaplar (bo'shliqlar) — SERIAL BILAN BIR XIL MANTIQ

```
IDENTITY COLUMN — ICHKARIDA, BARIBIR, ODDIY SEQUENCE OBYEKTIDAN
FOYDALANADI — SHUNING UCHUN, SERIAL'DAGI KABI, TRANSACTION
ROLLBACK QILINGANDA YOKI SERVER QAYTA ISHGA TUSHIRILGANDA
(CACHE'DAGI QIYMATLAR YO'QOLGANDA) — RAQAMLAR ORASIDA
"GAPLAR" (bo'shliqlar) PAYDO BO'LISHI ODDIY, KUTILGAN HODISA
(docs/Junior-B/database-design/primary-key-unique-identifier-
principles.md'da BATAFSIL YORITILGAN).
```

## 5. Code (Amaliy kod)

```sql
-- Tavsiya etiladigan, zamonaviy usul — GENERATED ALWAYS AS IDENTITY
CREATE TABLE employees (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL
);

-- Migratsiya/import uchun ko'proq moslashuvchan variant
CREATE TABLE legacy_import (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    old_system_id INT,
    name VARCHAR(100)
);

-- GENERATED BY DEFAULT — qo'lda qiymat kiritishga RUXSAT BERADI
INSERT INTO legacy_import (id, old_system_id, name) VALUES (500, 12345, 'Eski yozuv'); -- ✅ Ishlaydi

-- Sequence'ning keyingi qiymatini, qo'lda kiritilgan ID'lardan KEYINGI holatga SOZLASH
SELECT setval(pg_get_serial_sequence('legacy_import', 'id'), (SELECT MAX(id) FROM legacy_import));
```

```csharp
// EF Core — Identity Column konfiguratsiyasi
public class AppDbContext : DbContext
{
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Employee>()
            .Property(e => e.Id)
            .UseIdentityAlwaysColumn(); // GENERATED ALWAYS AS IDENTITY

        modelBuilder.Entity<LegacyImport>()
            .Property(l => l.Id)
            .UseIdentityByDefaultColumn(); // GENERATED BY DEFAULT AS IDENTITY
    }
}
```

## 6. Keng tarqalgan xatolar / noto'g'ri tushunchalar

```
❌ "SERIAL va GENERATED AS IDENTITY — FUNKSIONAL JIHATDAN
   TO'LIQ BIR XIL, FARQ FAQAT SINTAKSISDA" — QISMAN NOTO'G'RI!
   ASOSIY FARQ — GENERATED ALWAYS, QO'LDA QIYMAT KIRITISHGA
   YO'L QO'YMAYDI (nazorat kuchliroq), SERIAL ESA — ODDIY
   DEFAULT bo'lgani uchun, ISTALGAN QIYMATNI YOZISHGA RUXSAT
   BERADI.

❌ "PostgreSQL DOKUMENTATSIYASIDA, SERIAL — YANGI LOYIHALARDA
   HAM TO'LIQ TAVSIYA ETILADI" — YO'Q, RASMIY PostgreSQL
   DOKUMENTATSIYASI, YANGI LOYIHALARDA, `GENERATED ... AS
   IDENTITY`NI, SQL STANDARTIGA MOSLIGI VA QAT'IYROQ NAZORATI
   TUFAYLI TAVSIYA QILADI.

❌ "GENERATED ALWAYS AS IDENTITY'ga, HECH QANDAY HOLATDA,
   QO'LDA QIYMAT KIRITIB BO'LMAYDI" — TO'LIQ TO'G'RI EMAS!
   MAXSUS `OVERRIDING SYSTEM VALUE` SINTAKSISI ORQALI, ONGLI
   RAVISHDA, QO'LDA QIYMAT KIRITISH MUMKIN (masalan data
   migration uchun) — LEKIN BU, ODDIY INSERT'da AVTOMATIK
   ISHLAMAYDI, ANIQ NIYAT BILAN YOZILISHI SHART.

❌ "Identity column ishlatilsa, sequence gap (bo'shliq)
   MUAMMOSI BUTUNLAY YO'QOLADI" — YO'Q! Identity column,
   ICHKARIDA, BARIBIR SEQUENCE'GA ASOSLANGANI UCHUN, ROLLBACK
   VA SERVER RESTART TUFAYLI YUZAGA KELADIGAN GAPLAR — BARIBIR
   YUZAGA KELISHI MUMKIN.
```

## 7. Exam (Interview savollari)

**1. `SERIAL` va `GENERATED ALWAYS AS IDENTITY` orasidagi
ASOSIY, AMALIY FARQ nima?**
`SERIAL` — ODDIY DEFAULT MEXANIZMI (SEQUENCE + DEFAULT
nextval()) — ODDIY FOYDALANUVCHI, ID USTUNIGA, ISTALGAN
QIYMATNI ANIQ YOZISHI MUMKIN. `GENERATED ALWAYS AS IDENTITY`
— BUNGA UMUMAN YO'L QO'YMAYDI (`OVERRIDING SYSTEM VALUE`
maxsus sintaksisi bo'lmasa), NAZORAT ANCHA QAT'IYROQ.

**2. `GENERATED ALWAYS` va `GENERATED BY DEFAULT` orasidagi
FARQ nima?**
`GENERATED ALWAYS` — QO'LDA QIYMAT KIRITISHGA (`OVERRIDING
SYSTEM VALUE`siz) YO'L QO'YMAYDI. `GENERATED BY DEFAULT` —
ODDIY INSERT'da QO'LDA QIYMAT KIRITISHGA RUXSAT BERADI (SERIAL
GA O'XSHASH, LEKIN SQL STANDARTIGA MOS SINTAKSIS BILAN).

**3. Nima uchun PostgreSQL RASMIY DOKUMENTATSIYASI, YANGI
LOYIHALARDA, `SERIAL` O'RNIGA `GENERATED ... AS IDENTITY`NI
TAVSIYA QILADI?**
Chunki `GENERATED ... AS IDENTITY` — SQL:2003 STANDARTIGA
MOS (boshqa DB'larga ko'chirish osonroq), VA ID'LARNING
NAZORATSIZ, TASODIFIY O'ZGARISHINING OLDINI OLISHDA (ayniqsa
`ALWAYS` variantida) ANCHA QAT'IYROQ.

**4. `OVERRIDING SYSTEM VALUE` sintaksisi QACHON KERAK
BO'LADI?**
`GENERATED ALWAYS AS IDENTITY` bo'lgan USTUNGA, ONGLI
RAVISHDA, ANIQ, QO'LDA QIYMAT KIRITISH KERAK BO'LGANDA
(masalan, ESKI TIZIMDAN MA'LUMOTLARNI, ULARNING ASL ID
QIYMATLARI BILAN KO'CHIRISHDA/MIGRATSIYA QILISHDA).

**5. Identity Column ISHLATILGANDA HAM, SEQUENCE'DA "GAPLAR"
(bo'shliqlar) PAYDO BO'LISHI MUMKINMI? Nima uchun?**
Ha, MUMKIN! Chunki Identity Column, ICHKARIDA, BARIBIR
ODDIY SEQUENCE OBYEKTIGA ASOSLANADI — TRANSACTION ROLLBACK
QILINGANDA YOKI SERVER QAYTA ISHGA TUSHIRILGANDA (sequence
cache yo'qolganda) — SERIAL'DAGI KABI, GAPLAR YUZAGA KELISHI
ODDIY, KUTILGAN HODISA.
