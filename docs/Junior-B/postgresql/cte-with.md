# CTE (WITH) — Junior B

## 1. What (Nima?)

**CTE (Common Table Expression)** — `WITH` KALIT SO'ZI ORQALI
YARATILADIGAN, **VAQTINCHALIK, NOMLANGAN SO'ROV NATIJASI** —
U, ASOSIY SO'ROV ICHIDA, **XUDDI VAQTINCHALIK JADVAL KABI**
ISHLATILISHI MUMKIN. CTE — MURAKKAB SO'ROVLARNI, **MANTIQIY
QISMLARGA BO'LIB, O'QILISHI OSONROQ** QILADI, VA **REKURSIV
(o'z-o'ziga murojaat qiluvchi) SO'ROVLARNI** YOZISH IMKONINI
BERADI.

## 2. Real hayot analogiyasi

**CTE — RETSEPTDAGI "OLDINDAN TAYYORLANGAN SOUS" QADAMI.**
MURAKKAB TAOM RETSEPTI (katta SQL so'rov) — BIR NECHTA
QADAMDAN IBORAT: "AVVAL SOUSNI TAYYORLANG (1-qadam), KEYIN
UNI ASOSIY TAOMGA QO'SHING (2-qadam)". Agar SIZ HAMMA
NARSANI BIR VAQTDA, BITTA "KATTA, ARALASH" QADAMDA YOZSANGIZ
— RETSEPT O'QISHGA QIYIN BO'LADI. CTE — "AVVAL BUNI HISOBLA,
KEYIN NATIJANI, KEYINGI QADAMDA ISHLAT" DEGAN, TARTIBLI,
BOSQICHMA-BOSQICH YONDASHUVNI TA'MINLAYDI.

## 3. Why (Nega kerak?)

Murakkab SO'ROVLARNI, **ICHMA-ICH SUBQUERY** (nested subquery)
sifatida yozish — **O'QISH VA DEBUG QILISHNI QIYINLASHTIRADI**
(5-6 QAVAT ICHMA-ICH PARANTEZ). CTE — HAR QADAMGA **ANIQ NOM**
BERISH (masalan `WITH high_earners AS (...)`) ORQALI, SO'ROVNI,
**YUQORIDAN PASTGA, MANTIQIY KETMA-KETLIKDA O'QISH** IMKONINI
BERADI. Bundan TASHQARI, CTE — **REKURSIV STRUKTURALARNI**
(masalan XODIM-MENEJER IYERARXIYASI) SO'ROV QILISHNING
**YAGONA STANDART YO'LI**.

## 4. Internals (Ichki mexanizm)

### PostgreSQL 12+ — CTE "Inlining" OPTIMIZATSIYASI

```
ESKI POSTGRESQL VERSIYALARIDA (12'dan OLDIN), HAR CTE —
"OPTIMIZATION FENCE" (optimizatsiya to'sig'i) SIFATIDA
ISHLAR EDI: PostgreSQL, CTE'NI **ALOHIDA, MUSTAQIL RAVISHDA**
BAJARAR, NATIJANI VAQTINCHALIK "MATERIALLASHTIRAR" (diskka/
xotiraga yozar) EDI — QUERY PLANNER, CTE ICHIGA "KIRIB",
TASHQI SO'ROV BILAN BIRGALIKDA OPTIMALLASHTIRA OLMAS EDI.

POSTGRESQL 12+ DA — CTE'LAR, ODATDA, ODDIY SUBQUERY KABI
"INLINE" QILINADI (agar REKURSIV bo'lmasa va bir necha marta
ishlatilmasa) — QUERY PLANNER, BUTUN SO'ROVNI (CTE + tashqi
qism) BIRGALIKDA OPTIMALLASHTIRISHI MUMKIN.
```

### `MATERIALIZED` vs `NOT MATERIALIZED` — QO'LDA BOSHQARISH

```sql
WITH high_earners AS MATERIALIZED (
    SELECT * FROM employees WHERE salary > 5000000
)
SELECT * FROM high_earners WHERE department_id = 3;
```

```
MATERIALIZED — CTE'NI, MAJBURIY RAVISHDA, ALOHIDA
"VAQTINCHALIK NATIJA" SIFATIDA HISOBLAB, KEYIN TASHQI SO'ROVDA
ISHLATISHGA MAJBURLAYDI (ESKI XATTI-HARAKAT). BU, CTE BIR
NECHTA MARTA ISHLATILGANDA (masalan REKURSIV yoki KATTA
HISOBLASH TALAB QILUVCHI QISM UCHUN) — TAKRORIY HISOBLASHNI
OLDINI OLISHDA FOYDALI BO'LISHI MUMKIN.

NOT MATERIALIZED — CTE'NI, IMKON QADAR, TASHQI SO'ROV BILAN
"INLINE" QILISHGA (query planner OPTIMIZATSIYA QILISHIGA)
IMKON BERADI — ODATDA TEZROQ.
```

### Recursive CTE — `UNION ALL` bilan ITERATSIYA

```sql
WITH RECURSIVE org_chart AS (
    -- ANCHOR (asos) — boshlang'ich qator(lar)
    SELECT id, full_name, manager_id, 1 AS level
    FROM employees WHERE manager_id IS NULL

    UNION ALL

    -- RECURSIVE (rekursiv) qism — o'ziga murojaat qiladi
    SELECT e.id, e.full_name, e.manager_id, oc.level + 1
    FROM employees e
    JOIN org_chart oc ON e.manager_id = oc.id
)
SELECT * FROM org_chart ORDER BY level;
```

```
RECURSIVE CTE — ICHKARIDA, "ANCHOR" QISMNI BIR MARTA
BAJARADI, KEYIN, "RECURSIVE" QISMNI, HAR ITERATSIYADA,
OLDINGI ITERATSIYA NATIJASI ("org_chart" o'zi) ASOSIDA,
TAKRORLAB BAJARADI — TA QISMLARDAN BIRORTASI HAM YANGI QATOR
QAYTARMAGUNCHA (bo'sh natija) DAVOM ETADI. Bu, DARAXTSIMON
(TREE) STRUKTURALARNI (menejer-xodim iyerarxiyasi, kategoriya-
subkategoriya) SO'ROV QILISHNING STANDART USULI.
```

## 5. Code (Amaliy kod)

```sql
-- Oddiy CTE — kodni "bosqichma-bosqich" o'qish uchun
WITH department_totals AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
),
above_average AS (
    SELECT department_id, total_salary
    FROM department_totals
    WHERE total_salary > (SELECT AVG(total_salary) FROM department_totals)
)
SELECT d.name, a.total_salary
FROM above_average a
JOIN departments d ON d.id = a.department_id;

-- Recursive CTE — xodim-menejer iyerarxiyasi (organigramma)
WITH RECURSIVE org_chart AS (
    SELECT id, full_name, manager_id, 1 AS level
    FROM employees WHERE manager_id IS NULL

    UNION ALL

    SELECT e.id, e.full_name, e.manager_id, oc.level + 1
    FROM employees e
    JOIN org_chart oc ON e.manager_id = oc.id
)
SELECT REPEAT('  ', level - 1) || full_name AS org_tree
FROM org_chart ORDER BY level;
```

// EF Core — CTE, ODATDA, LINQ orqali to'g'ridan-to'g'ri qo'llab-quvvatlanmaydi,
// murakkab CTE uchun RAW SQL ishlatiladi
var results = await dbContext.Database
    .SqlQuery<DepartmentTotal>($@"

            SELECT department_id AS ""DepartmentId"", SUM(salary) AS ""TotalSalary""
            FROM employees
            GROUP BY department_id
        )
        SELECT * FROM department_totals WHERE ""TotalSalary"" > 10000000
    ")

## 6. Keng tarqalgan xatolar / noto'g'ri tushunchalar

```
❌ "CTE — HAR DOIM, MAJBURIY RAVISHDA, ALOHIDA HISOBLANIB,
   'MATERIALIZE' QILINADI" — PostgreSQL 12'GACHA TO'G'RI EDI,
   LEKIN 12+ DA, ODATDA, CTE — QUERY PLANNER TOMONIDAN
   "INLINE" QILINADI (agar MATERIALIZED ANIQ SO'RALMASA) —
   PERFORMANCE, ODDIY SUBQUERY BILAN DEYARLI BIR XIL.

❌ "CTE — FAQAT REKURSIV SO'ROVLAR UCHUN ISHLATILADI" — YO'Q,
   CTE — ODDIY, ODDIY (NON-RECURSIVE) SO'ROVLARNI, KODNI
   O'QISH VA TUZILISHINI YAXSHILASH UCHUN HAM KENG
   ISHLATILADI.

❌ "Recursive CTE — CHEKSIZ AYLANIB QOLISHI MUMKIN EMAS" —
   XATO! Agar MA'LUMOTLARDA "AYLANMA" BOG'LIQLIK BO'LSA
   (masalan A→B→A), YOKI ANCHOR/TERMINATSIYA SHARTI NOTO'G'RI
   YOZILSA — RECURSIVE CTE CHEKSIZ AYLANIB QOLISHI MUMKIN —
   PostgreSQL'da BUNI CHEKLASH UCHUN, ODATDA `LIMIT` YOKI
   ANIQ TERMINATSIYA SHARTI QO'SHILADI.

❌ "MATERIALIZED va NOT MATERIALIZED — BIR XIL PERFORMANCE
   BERADI" — YO'Q, HAR IKKISI, TURLI STSENARIYLARDA, TURLICHA
   TEZLIKKA EGA BO'LISHI MUMKIN — CTE BIR NECHTA MARTA
   ISHLATILGANDA, MATERIALIZED — TAKRORIY HISOBLASHNI
   OLDINI OLISHI MUMKIN, LEKIN BIR MARTA ISHLATILGANDA,
   NOT MATERIALIZED (INLINE) — ODATDA TEZROQ.
```

## 7. Exam (Interview savollari)

**1. CTE (WITH) nima, va u SUBQUERY'DAN NIMASI BILAN
FARQ QILADI?**
CTE — `WITH` KALIT SO'ZI ORQALI YARATILADIGAN, NOMLANGAN,
VAQTINCHALIK SO'ROV NATIJASI — SO'ROVNI, MANTIQIY QISMLARGA
BO'LIB, O'QISHNI OSONLASHTIRADI. Ichma-ich SUBQUERY'DAN FARQLI
O'LAROQ, CTE — ANIQ NOMGA EGA VA BIR NECHTA MARTA (yoki
REKURSIV) ISHLATILISHI MUMKIN.

**2. PostgreSQL 12+ da, CTE'ning "OPTIMIZATION FENCE" 
XATTI-HARAKATI QANDAY O'ZGARDI?**
PostgreSQL 12'gacha, HAR CTE — MAJBURIY RAVISHDA ALOHIDA
MATERIALLASHTIRILAR EDI (Query Planner, CTE ICHIGA "KIRA"
OLMAS EDI). 12+ DA, ODATDA, CTE — ODDIY SUBQUERY KABI
"INLINE" QILINADI (agar MATERIALIZED ANIQ SO'RALMASA) —
Planner, BUTUN SO'ROVNI BIRGALIKDA OPTIMALLASHTIRISHI
MUMKIN.

**3. Recursive CTE'ning IKKI ASOSIY QISMI (ANCHOR va
RECURSIVE) NIMANI ANGLATADI?**
ANCHOR (asos) — BOSHLANG'ICH, "ILDIZ" QATORLARNI TANLAYDI
(masalan menejeri YO'Q xodimlar). RECURSIVE (rekursiv) qism —
OLDINGI ITERATSIYA NATIJASI ASOSIDA, YANGI QATORLARNI
QO'SHIB BORADI, TA HECH QANDAY YANGI QATOR QAYTARILMAGUNCHA
(bo'sh natija) DAVOM ETADI.

**4. `MATERIALIZED` va `NOT MATERIALIZED` CTE orasidagi FARQ
nima, va QAYSI HOLATDA MATERIALIZED FOYDALI BO'LISHI MUMKIN?**
`MATERIALIZED` — CTE'NI, MAJBURIY RAVISHDA, ALOHIDA
HISOBLAB, VAQTINCHALIK NATIJA SIFATIDA SAQLAYDI.
`NOT MATERIALIZED` — Query Planner'ga, CTE'NI TASHQI SO'ROV
BILAN "INLINE" QILISHGA IMKON BERADI. MATERIALIZED — CTE
BIR NECHTA MARTA ISHLATILGANDA, YOKI MURAKKAB, QIMMAT
HISOBLASH TALAB QILGANDA, TAKRORIY HISOBLASHNI OLDINI OLISH
UCHUN FOYDALI BO'LISHI MUMKIN.

**5. Recursive CTE, QAYSI TURDAGI REAL LOYIHA STSENARIYSIDA
ENG KO'P ISHLATILADI?**
DARAXTSIMON (TREE) YOKI IYERARXIK STRUKTURALARNI SO'ROV
QILISHDA — masalan, XODIM-MENEJER ORGANIGRAMMASI, KATEGORIYA-
SUBKATEGORIYA DARAXTI, KOMMENTARIYALAR (nested comments)
DARAXTI — BULARNING BARCHASI, "O'Z-O'ZIGA ISHORA QILUVCHI"
(self-referencing) STRUKTURAGA EGA, VA Recursive CTE — ULARNI
SO'ROV QILISHNING STANDART, SAMARALI YO'LI.
